# 이력 자료 공개 기준

이 저장소에는 경력 설명과 마스킹 검토를 마친 자료만 보관합니다. 프로젝트 원본은 로컬 프로젝트 폴더에 보관하고, 공개할 내용은 별도 문서로 작성합니다.

## 다음 프로젝트를 정리할 때

- 기존 상세 경력기술서의 배경 → 담당 범위 → 수행 내용 → 문제 해결 → 결과 형식을 따릅니다.
- 팀 전체 산출물과 본인의 기여를 구분합니다. 파일이 존재한다는 이유만으로 운영 완료나 성과 달성을 적지 않습니다.
- 금액, 수량, 고객 실적, 비율과 비용은 `[마스킹]`으로 바꾸거나 수치 없는 설명으로 씁니다. 숫자를 한글로 바꾸는 것은 마스킹이 아닙니다.
- 경력 기간, 문서 기준일, 목차 번호와 제품 이름은 문맥에 필요한 공개 정보로 유지합니다.
- 연락처, 고객별 거래 내역, 계정·접속 정보, 내부 경로는 제거합니다.
- 엑셀, CSV, 데이터베이스, 노트북 출력, 압축파일, Tableau 워크북·추출본, 고객 원본 문서는 올리지 않습니다.
- 새 화면 이미지는 수치뿐 아니라 회사명·로고·상품명·거래처·연락처·툴팁까지 검토해야 합니다. 자동 검사는 새 이미지와 변경 이미지를 기본 차단합니다.

## Git 훅 설치

PowerShell에서 저장소의 `scripts/install-hooks.ps1`을 실행하며 설치된 Python 실행 파일을 지정합니다.

```powershell
./scripts/install-hooks.ps1 -PythonPath (Get-Command python).Source
```

명령의 Python이 실행되지 않으면 실제 Python 실행 파일의 경로를 지정합니다. 설치는 해당 저장소에만 적용되며 기존의 다른 훅 설정이 있으면 덮어쓰지 않고 중단합니다.

macOS 또는 Linux에서는 Python 설치 후 아래 명령으로 활성화할 수 있습니다.

```sh
git config core.hooksPath .githooks
```

다른 저장소에도 적용하려면 `.githooks`, `scripts/privacy_guard.py`, `scripts/privacy_policy.json`과 설치 스크립트를 복사하고 다시 설치합니다. 기존 이미지·URL 예외 목록은 대상 저장소에 맞게 검토해야 합니다. 이 정책은 문서 중심의 이력 저장소용으로, 일반 소스코드 저장소에는 그대로 적용하지 않습니다.

## 검사 범위

`pre-commit`은 작업 파일이 아닌 Git 스테이지 전체를 검사합니다. 파일 유형·경로, 마스킹되지 않은 숫자, 연락처·토큰·내부 위치와 바이너리 위장을 확인합니다.

`pre-push`는 새로 전송하는 커밋을 각각 검사합니다. 데이터 파일을 커밋했다가 다음 커밋에서 지워도 전송 이력에 남아 있으면 차단합니다. 검사에 실패하거나 Python을 찾지 못하면 커밋·푸시를 중단합니다.

기존에 공개된 마스킹 이미지에는 파일별 해시 예외가 있습니다. 이미지가 바뀌면 다시 검토하기 전까지 차단됩니다. 기존 프로필 링크·배지는 정확히 일치하는 주소만 숫자 검사에서 제외합니다. 훅·검사기·테스트·정책 파일에는 코드와 테스트용 숫자가 필요하므로 정해진 경로만 허용합니다. 해당 파일의 변경은 직접 검토해야 합니다.

GitHub Actions도 문서와 커밋 이력을 검사합니다. Actions는 업로드 이후 실행되므로 업로드 방지는 로컬 훅이 담당합니다. 다른 PC에서 복제하면 훅을 다시 설치해야 하며, Git 훅은 강제로 우회할 수 있으므로 게시 전 수동 검토를 대체하지 않습니다.
