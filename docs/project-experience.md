## 📊 ADAPT 프로젝트

**2026.08.25 ~ 현재 | 데이터 플랫폼 운영·개선 · 데이터 모델 관리 · 매출 정합성 검증**

여러 판매 채널의 주문·결제·취소·반품 데이터를 공통 기준으로 연결하는 커머스 데이터 플랫폼을 인수해 운영·개선하고 있습니다. AWS와 dbt 기반 처리 흐름부터 Salesforce Data Cloud, Tableau Prep·Next의 분석 데이터까지 연결해 지표 차이가 생기는 구간을 추적합니다.

### 1. 공통 데이터 모델과 매출 기준 관리

- 채널별 원천 구조를 파악하고 주문·배송·클레임·결제 데이터를 공통 모델로 정규화하는 dbt 모델과 Athena VIEW를 관리합니다.
- 취소·교환·환불의 상태와 적용 날짜, 상품·옵션 매핑, 결제·할인·배송비의 반영 기준을 비교해 집계 차이의 원인을 분석합니다.
- 원천 데이터, 변환 모델, 분석용 집계 결과를 단계별로 대사하고 변경 전후 결과를 비교합니다.

### 2. Tableau Prep 매출·환불 로직 보정

- 환불 수량과 금액을 원주문에 연결하고, 교환 전후 라인과 반복 환불 기록에서 중복 집계가 발생하는 조건을 점검했습니다.
- 순결제 금액을 넘는 환불과 할인 배분 문제를 보정한 흐름 파일을 작성하고, 출력 구조와 변경 범위를 검사했습니다.
- 한국 시간 기준 매출일, 미고시일의 직전 환율 이월, 분류불가 사유 진단을 반영한 수정본을 준비했습니다.
- 취소 배송비 반영은 후속 수정 파일을 확보한 단계이며, 운영 배포와 실제 집계 결과의 최종 검증은 별도로 확인합니다.

### 3. Data Cloud 처리량 원인 분석과 변경분 전송

- 반복 적재 비용을 살펴보며 중복 데이터와 매 회차 전체 이력 전송을 구분해 원인을 분석했습니다.
- Amazon 주문의 최근 변경분을 대상으로 export하도록 전환하고, 기존 결과와의 스키마·값 비교 및 되돌리기 절차를 정리했습니다.
- 전송 행수와 예상 크레딧은 **[마스킹]** 처리했습니다. 실제 운영 비용 절감은 후속 회차의 처리 결과와 과금 확인 전까지 확정 성과로 기재하지 않습니다.

### 4. 검증 기록과 운영 문서화

- 채널별 대사, 변경 범위, 구조 검사 결과와 미결 항목을 기록해 후속 검증에 활용합니다.
- 데이터 흐름과 적재·매핑·갱신 절차를 정리하고, BI 지표 문의에 원천과 변환 과정의 근거를 연결합니다.

### 1. 매출 KPI와 실적 비교 화면

- 연간 목표, MOA, 목표 대비 달성률, 실현 매출을 요약하고 월별 추이를 비교하도록 기획했습니다.
- 국가·담당자·계약 조건별 차이를 살펴보고 선택한 항목이 상세 내역에 연결되도록 화면의 필터 흐름을 정리했습니다.

### 2. 신규 바이어 영업 파이프라인

- 리드에서 컨택·미팅·샘플·거래처 전환으로 이어지는 진행 단계를 시각화했습니다.
- 단계별 KPI와 담당자별 현황을 비교할 수 있도록 메뉴, 요약 지표, 게이지와 비교 영역을 디자인하고 개발했습니다.

### 3. 전달 산출물과 데이터 관리 가이드

- 기획안 수정본, Tableau 전달용 워크북과 데이터 관리 가이드를 정리했습니다.
- 화면 검토와 데이터 갱신에 필요한 자료를 함께 구성해 PoC의 전달 맥락을 남겼습니다.
